# Public launch checklist

## Product readiness

- [ ] Install and build the frontend on a clean machine with Node 22.
- [ ] Run API tests and validate all resource/path references.
- [ ] Manually test responsive layouts, keyboard navigation, screen-reader labels and color contrast.
- [ ] Review external link behavior, redirects and unsafe destinations.
- [ ] Audit and refresh the highest-priority resource metadata.
- [ ] Decide a project license and confirm rights to all submitted material.

## Operational readiness

- [ ] Deploy behind HTTPS and a production reverse proxy.
- [ ] Restrict CORS to the production frontend origin.
- [ ] Configure database backups and a tested restore procedure.
- [ ] Configure logs, error monitoring, availability checks and dependency updates.
- [ ] Add request throttling and abuse protection before enabling write endpoints.

## Community readiness

- [ ] Publish contribution standards and review expectations.
- [ ] Establish maintainer responsibilities and escalation paths.
- [ ] Add a transparent removal/correction process.
- [ ] Publish privacy and terms documents before adding analytics, accounts or user submissions.

## Growth measurement

Measure useful outcomes—successful discovery, resource opens, search refinements, broken-link correction time, pathway progression and accessibility—not raw page views alone. Collect analytics only after a privacy review and with clear user notice.
